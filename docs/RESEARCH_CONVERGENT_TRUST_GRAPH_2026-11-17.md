## Directly reproduced SZL source gap and actual adaptation

The mesh already carries `Op.op_id = SHA256(canonical(doc,key,value,lamport,node,deletion))` and locally records `track` (AUTHORIZED/OBSERVED/REVOKED) outside that identity. Before this change `CRDTDocument.add_op` returned without touching state if an op ID was present. Therefore two replicas with identical operation bytes but different authorization classifications could merge in either direction and disagree about what was actionable. The initial new test suite reproduced **39 failing cases** (including authorization conflicts and malformed labels) before the code change. This is a concrete example of the kind of apparent-permission amplification discussed in [EAL-Bench](https://arxiv.org/abs/2609.01836); the paper's empirical rates do not apply automatically to SZL.

The candidate software rule for *one identical operation ID* is the conservative join-semilattice

```text
AUTHORIZED < OBSERVED < REVOKED
track_join(a,b) = max_risk(a,b)
```

The join laws `a ⊔ b = b ⊔ a`, `(a ⊔ b) ⊔ c = a ⊔ (b ⊔ c)`, and `a ⊔ a = a` give arrival-order independence for the bounded three-element track vocabulary. Existing LWW payload order `(lamport, node_id, op_id)` remains unchanged. Incoming classifications are data, **not signer authentication**.

A disputed AUTHORIZED/OBSERVED label resolves to **OBSERVED** until a *local Receipt Gate* verifies a valid receipt; a REVOKED label is absorbing even under repeated valid reissues. `Node.apply_remote` already independently validates signed incoming evidence and can retain/recheck previous evidence; its two promotion paths now explicitly supply `validated=True` only on a successful local gate. Reporting from `apply_remote` now uses the **effective** stored track, not a stale gate decision. The transport op shape is unchanged. Unknown track values, explicit serialized op-ID mismatches, and distinct-content same-hash collisions fail closed.

This is an **empirically tested Python finite-state property**, not a Lean theorem, live network proof, BFT safety result, or witness-authority attestation. It does not update locked doctrine or prove Conjecture 1 or Conjecture 2. The policy guard `validated=True` is an internal boundary; callers must not mistake a Boolean for a cryptographic signature.

## Next system architecture, intentionally not claimed as implemented

1. **Proof-Carrying Temporal Ontology**: for each graph edge store `tenant, source_episode_hash, valid_from, valid_to, recorded_at, policy_head, signature_reference, witness_root, revocation_reference` and a role-scoped author. Preserve superseded claims as time-specific OBSERVED evidence.
2. **Eligibility before relevance**: require `tenant_match ∧ actor_scope ∧ receipt_valid ∧ policy_current ∧ (valid_at ≤ query_time < valid_to) ∧ ¬revoked`. Unknown or unverifiable evidence is UNAVAILABLE or DENIED, never boosted by similarity. Apply RRF only to surviving eligible records.
3. **Durable execution**: transactionally record `intent_id` and `effect_id`, separately bind a witness verification receipt, and enforce replay-safe idempotency across crashes and concurrent writers. The current in-memory Mesh CRDT plus local receipts does **not** by itself provide such a ledger.
4. **Topology measurement**: compare mean local clustering `C = avg_v[2 triangles(v)/(degree(v)(degree(v)-1))]`, mean finite-path length `L = avg_(u!=v) distance(u,v)`, and exhaustive survivor connectivity `S_f = (# connected induced subgraphs after exactly f node failures)/choose(n,f)`. Report `S_f` as **SIMULATED**, never a certificate of Byzantine quorum safety.
5. **Graph/receipt consumer alignment**: require Hatun, A11oy, Mesh, Frontier, Khipu, the lake and Anatomy to emit the same typed entity/receipt references and preserve READ_ONLY vs ACTION/COMMITTED distinctions. A UI cannot invent missing upstream witness results.
6. **Benchmark the claim**: compare the existing pure-LWW/CRDT implementation to the bounded join on conflicting-track fixtures, then evaluate retrieval answer correctness, cross-tenant leak rate (target zero), policy bypass rate (target zero), p95 latency, storage overhead, and crash replay. No claims of superiority without an external evaluation set.

**Scope of this change:** only the mathematically bounded mesh classification join, its local gate integration, regression fixtures, and CI wiring. It does **not** modify `mesh_command` UI or remotely deploy a service. Do not conflate an implementation plan with a working distributed database.

## Tests and admission

Local exact-worktree execution of `python -m pytest -q -rs tests` returned **245 passed, 1 skipped**, exit 0 (the optional `szl_receipt` library was not installed on this workstation, so the canonical spine test module honestly skipped; the protected CI spine job installs it). `python -m ruff check` on all touched Python modules and tests, `compileall`, and `git diff --check` each passed. The finite tests cover all 3² pairs, 3³ triples with delivery permutations, explicit join laws, 120 seeded multi-key reorder trials, signed/unsigned Node replay, persistent revocation, malformed tracks and op-ID tampering. The focused source tests are added to the existing protected `receipt-gate` and `test-runtime-trust` workflows. Hosted exact-head CI and independent review are separate requirements. Signer keys, runtime credentials, HF/CF deployment settings, and historical signed receipts are untouched.
